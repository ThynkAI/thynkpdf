# THYNKPDF v0.2.0 — release readiness

THYNKPDF is free, so it has **no accounts and no sign-in**.

## Identity and local API security
| Build | Identity |
|---|---|
| Desktop | One local workspace is provisioned on first launch. Provisioning is idempotent, and documents of the v0.1.7 `local@desktop.thynkpdf.app` account are kept. |
| Hosted web | `THYNKPDF_AUTH_MODE=anonymous` (the default): one private workspace per browser, keyed by a random browser key in localStorage. |
| Accounts | Legacy email/password (`THYNKPDF_AUTH_MODE=accounts`). Opt-in only, used by the API test suite. |

The desktop sidecar's API stays protected:
- Electron generates a random 256-bit key per launch and passes it to the sidecar via env.
- Every API route requires `X-Thynkpdf-Key`. The renderer gets the key via preload (`window.thynkpdf.apiKey()`, origin-checked IPC), and the `app://` handler also attaches it.
- Host must be `127.0.0.1:<port>` or `localhost:<port>`.
- A present Origin must be the app's own origin.
- `/auth/register` and `/auth/login` return `ACCOUNTS_DISABLED`.

There is no refresh-token or session-expiry UI. Tokens are renewed silently via `POST /session/local`.

## Audit findings fixed in this release
| ID | Change |
|---|---|
| BD-01 | Feature routers are imported statically and added as `--hidden-import`. `smoke_sidecar.py` asserts that the packaged OpenAPI operations equal the source app's (80 = 80), then runs annotations, form fields and fill, signature placement, and rotate/duplicate/delete, verified with pypdf. It also covers restart persistence and permissions. FUX-02 is re-checked on the AppImage: forms 200 and Ask 200. Signature requests are deliberately 403 `DESKTOP_LOCAL_ONLY` (BD-06). |
| BD-02 | No-account bootstrap, as described above. |
| BD-03 | `backend-tests.yml` (pytest) added. The desktop release `needs` backend-tests and web-e2e on the tag commit. The release adds `SHA256SUMS` and notes. |
| BD-04 / BD-07 | Desktop startup runs Alembic: `quick_check`, stamp of legacy `create_all` DBs, an SQLite online backup to `backups/` (last 5 kept), and `upgrade head`. A DB from a newer version is refused. On failure the app shows a dialog with "Open data folder" and the data is untouched. |
| BD-05 | Host/Origin allowlist plus the per-launch key. Register/login are disabled. |
| BD-06 | On desktop, share links and remote signature requests are hidden or labelled "needs hosted server", and the API returns `DESKTOP_LOCAL_ONLY`. Visual signing on this device still works. |
| BD-09 | Duplicate page copies comments and links. Form widgets are not copied. |
| BD-11 | umask 077. The data dir is 0700 and files are 0600, including libraries created by older versions. |
| BD-12 | OCR claims removed. |
| BD-16 | `shell.openExternal` is limited to https. |
| BD-19 / FUX-10 | The UI is served from `app://thynkpdf` (a privileged, standard, secure scheme proxied to the sidecar), so localStorage and IndexedDB survive restarts. The AppImage restart check is verified. Older random-port origins changed on every launch, so there was no persistent storage to migrate. |
| BD-23 | MIT LICENSE added. Nothing was stated before, so MIT was chosen to match the free-app intent. |
| R4 / FUX-09 | Closing with unsaved in-browser edits asks for confirmation. |
