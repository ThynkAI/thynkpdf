### FUX-01 · Blocker (v0.1.6) → verified fixed in v0.1.7, regression risk · First-run access without an account
- **Category:** Confirmed defect at 7604fc5 / v0.1.6 AppImage. Verified working at bc7ee6b / v0.1.7 AppImage.
- **Mode:** desktop (packaged) and web.
- **Repro (v0.1.6):** fresh profile → launch AppImage → Documents → only Email/Password/Sign in. The DB `users` table has **0 rows**, there is no register UI anywhere in the bundle, and login returns `INVALID_CREDENTIALS`. Open a PDF → every page tool shows "Editing requires a document opened through the THYNKPDF server (sign in, then open)."
- **Expected:** a free local app works on first launch with no account. **Actual:** server tools cannot be reached.
- **Evidence:** `evidence/desktop-01-first-launch.png`, `evidence/desktop-02-documents-signin-wall.png`, `evidence/desktop-03-local-open-tools-disabled.png`. Test `FUX-01` (known-failing on 7604fc5).
- **Re-verify on bc7ee6b:** in the v0.1.7 AppImage, `provisionLocalSession()` creates `local@desktop.thynkpdf.app` (confirmed in the DB). Status reads "Local engine on this computer — works offline, no sign-in needed" (`evidence/bc7ee6b/desktop017-01-first-launch.png`). On the web, an unsigned user gets local pdf-lib page ops. I rotated `acroform-all.pdf` locally and downloaded it; pypdf shows `/Rotate 90`, and all 5 fields are retained. Test `FUX-01` now passes ("Expected to fail, but passed").
- **Risk:** open PR #33 reverts both the local gate and `provisionLocalSession`. If it merges, FUX-01 returns. Keep the test as a guard.
- **Owner:** Bot 1 (bootstrap contract) + web. **Acceptance:** with a fresh profile and no network, open a PDF; rotate/delete/reorder succeed and can be saved.

### FUX-02 · Blocker · Desktop server-backed tools fail with raw HTTP 404/405 (UI side of BD-01)
- **Category:** Confirmed defect. **Mode:** packaged desktop, v0.1.6 (after I added an account by hand) and **v0.1.7 by default**.
- **Repro (v0.1.7, fresh profile):** open `acroform-all.pdf` → the right panel "Form fields" shows `HTTP_404: GET /pdf/<id>/forms?version=1 failed: 404` and no fields. Sign → Request signatures → Create → `HTTP_405: POST /signature-requests failed: 405`, and the list stays on "Loading…" indefinitely. Ask → `HTTP_405: POST /ai/ask failed: 405`. The sidecar's `openapi.json` lists 23 routes, against 74 in source.
- **Expected:** working tools, or these tools hidden/labelled unavailable. **Actual:** a fillable form looks like it has no fields, and errors are raw protocol strings. v0.1.7 makes this worse: auto sign-in means every opened file now becomes a server document, so the server-only panels are always used.
- **Evidence:** `evidence/bc7ee6b/desktop017-05-forms-raw-404.png`, `desktop017-03-request-signatures.png`, `evidence/desktop-06-request-error.png` (v0.1.6). The probe output is in §5 of `user-journey-results.md`.
- **Root cause (Bot 1, BD-01):** `features/__init__.py` discovers modules with `pkgutil.iter_modules(__path__)`, which finds nothing in a PyInstaller archive. This is Bot 1's analysis, consistent with my route list.
- **Fix:** bundle the feature modules (explicit imports), and add a sidecar smoke step that asserts the route count. In the UI, show a plain message when a capability is missing and fall back to local pdf-lib forms.
- **Acceptance:** in a fresh v0.x AppImage, forms list 5 fields, fill+save works, and no `HTTP_` text appears anywhere.
- **Owner:** Bot 1 (sidecar), web (error UX).

### FUX-03 · High · Share/signer links use `window.location.origin` (loopback on desktop)
- **Category:** Source-level concern for desktop. The link UI could not be reached because of FUX-02, but the origin churn was measured.
- **Code:** `SharePanel.tsx:26` and `RequestSignatures.tsx:48` → `publicLinks.ts` `${origin}/sign/?token=` and `/shared/?token=`.
- **Measured:** the desktop origin is `http://127.0.0.1:<random>`. Three launches gave 44567, 56127 and 33533. Such a link is unreachable from another computer, and on this one it dies at the next launch.
- **Verified working:** the signer-link box says "**No email is sent.** Copy each private link…" (source, plus the existing E2E `phase2` request flow on the web). There is no false "email sent".
- **Fix:** in desktop mode, hide "Create public link"/"Request signatures", or label them "Only works on this computer while THYNKPDF is open".
- **Acceptance:** desktop build has no loopback URL copied to the clipboard without that warning.
- **Owner:** web + Bot 1 (BD-06).

### FUX-06 · Medium · Technical wording and raw error codes are shown to users
- **Category:** Confirmed defect. Observed strings:
  - `Edit text failed: TEXT_NOT_FOUND: Text not found within a single editable text run (Text split across runs/kerning is not matched)`
  - `EDIT_UNSUPPORTED_CHARACTERS: Characters not representable in the font's simple encoding`
  - `NO_TEXT_LAYER: No extractable text (scanned?). OCR is not available on this server yet.`
  - `HTTP_404: GET /pdf/…/forms?version=1 failed: 404`
  - `HTTP_405: POST /signature-requests failed: 405`
  - `Rotate failed: Failed to fetch`
  - Status bar `Source: backend|local|none`
  - Panel heading "Backend" (web) / "Engine" (desktop)
  - `Excerpt mode (stub)` (v0.1.6)
- **Proposed replacements** (keep the code in a "Details" disclosure or the log):

| Shown now | Proposed |
|---|---|
| TEXT_NOT_FOUND … single editable text run | "That text can't be edited here. It may be split into pieces inside the PDF. Try a shorter phrase, or a single word." |
| EDIT_UNSUPPORTED_CHARACTERS | "This PDF's font can't show some of those characters (for example accents or other scripts)." |
| NO_TEXT_LAYER … (scanned?) | "This looks like a scanned page with no selectable text, so it can't be searched or asked about yet." |
| HTTP_404/405 … failed | "This feature isn't available in this version of THYNKPDF." (plus a Details link) |
| Rotate failed: Failed to fetch | "Couldn't save the change: the THYNKPDF engine isn't responding. Your document wasn't changed. Try again." |
| Source: backend / local / none | "Saved in THYNKPDF" / "Opened from your computer (not saved yet)" / hide it |
| Backend / Engine | "Storage" or "Status" |

- **Evidence:** test `FUX-06`, `evidence/web-ai-scanned.png`, `evidence/bc7ee6b/desktop017-05-forms-raw-404.png`, `evidence/bc7ee6b/backend-killed-during-rotate.png`.
- **Owner:** web.

### FUX-07 · Medium · The fixed-height status bar clips long messages
- **Category:** Confirmed defect at 1024x700. The 200% variant is Blocked/unverified: the error element did not appear within the test's wait, cause not isolated.
- **Code:** `StatusBar.tsx`, `footer h-7 flex` with no truncation, wrapping or overflow handling.
- **Repro:** at 1024x700, open a non-PDF named with 108 characters. The footer's scrollHeight is 30 against clientHeight 27, so the text wraps onto two lines and the bottom line ("PDF structure.") is cut off. "No document" and "100% (fit width)" also wrap.
- **Evidence:** `evidence/statusbar-long-error-1024x700@1x.png`, test `FUX-07`.
- **Fix:** put errors in a dismissible banner/toast with `role=alert`; truncate the status items with a title/tooltip.
- **Owner:** web.

### FUX-08 · Low · The compress result hides the real change
- **Category:** Confirmed defect. A tiny PDF went from 1341 to 957 bytes (−29%, checked independently) but the UI said "Compressed: 1 KB → 1 KB (now v2)."
- **Blocked/unverified:** the "no reduction" message. No fixture grew under compression in the time available.
- **Fix:** show bytes below 10 KB and a percentage; if the saving is under ~2%, keep the original and say so.
- **Evidence:** `evidence/web-compress-tiny.png`, test `FUX-08`.

### FUX-09 · High (data loss) · No unsaved-changes guard
- **Category:** Confirmed defect, both commits. There is no `beforeunload` handler anywhere in `apps/web/src`. A synthetic `beforeunload` is not prevented after local markup.
- **Impact:** v0.1.7 makes it worse. Local page ops (rotate/delete/reorder) are now unsaved in-memory edits, and closing the window or tab, or reloading, discards them without a prompt. On desktop, Electron closes immediately.
- **Fix:** add a `beforeunload` handler while `annot.working.dirty`; in Electron, a `close` handler with a Save/Discard/Cancel dialog.
- **Evidence:** test `FUX-09`.
- **Owner:** web + Bot 1 (Electron close).

### FUX-10 · High · Desktop restart loses saved signatures and settings and does not reopen the document
- **Category:** Confirmed defect. GUI check on the v0.1.6 AppImage (this is Bot 1's BD-19).
- **Repro:** create a typed signature (saved-sigs count 1) and set the theme to dark → quit → relaunch. The port changed 56127→33533; saved-sigs is **0** and `tp-theme` is null. The IndexedDB `thynkpdf` exists, but it is the new origin's empty store. Separately, the last document is not reopened ("No document"), because persistence uses `sessionStorage`. The session cookie does survive: the app still shows "Connected".
- **Evidence:** `evidence/desktop-08-before-restart.png`, `evidence/desktop-09-after-restart.png`, probes `desk5/desk6`.
- **Fix:** use a fixed loopback port or a custom protocol (`app://`) so the origin is stable; persist the last document in `localStorage`.
- **Owner:** Bot 1.

### FUX-11 · Medium · v0.1.7 local page ops have a hidden, mislabelled save path

## 5. Accessibility (Stage 6) — what was checked
- **axe-core** (`@axe-core/playwright`): 5 viewports × home and editor (FUX-14). The existing suite also scans the empty editor, the editor with organizer/signature dialogs, and the signed-out and signed-in dashboard; it passed at 7604fc5.
- **Tab order** on home: header nav → toolbar → left tabs → tiles → tools pane. The order is logical, and all 25 stops show a visible focus style (outline or box-shadow).
- **Dialog:** trap fails; Escape works; focus restore fails (FUX-12).
- **Reduced motion:** the stylesheet contains `prefers-reduced-motion` rules.
- **Icon buttons** have names: "Rotate page clockwise", "Close organizer", "Toggle thumbnails", and so on.
- **Live regions:** errors use `role=alert`; compress/share results use `role=status`; the footer is `role=status`, so every page change is announced. That may be noisy (Product improvement).
- **Drag alternatives:** page reorder has a keyboard path (existing E2E "keyboard reorder"). The placed signature uses arrow keys and +/- per its aria-label.
- **Contrast:** axe reported no contrast violations. Not checked by hand.
- **Not done:** a screen-reader pass (NVDA/VoiceOver), Windows High Contrast, and 200% *text-only* zoom.
